# Семейный бюджет — заметки для разработки

## Что это
Одностраничное офлайн-приложение семейного бюджета. Весь код — в одном файле
`index.html` (HTML + CSS + JS, без сборки). Файл `family-budget-light.html`
держим **байт-в-байт идентичным** `index.html` (это копия для запасного URL).
После любой правки `index.html` нужно скопировать его поверх
`family-budget-light.html`.

## Хостинг и доставка
- Сайт публикуется через **GitHub Pages из ветки `main`** (workflow
  «pages build and deployment»).
- Рабочая версия пользователя — это и есть GitHub Pages. Изменения попадают
  к пользователю только после мёрджа в `main` и автодеплоя (1–3 мин).
- После деплоя часто нужен жёсткий рефреш браузера (Ctrl/Cmd+Shift+R) —
  кэшируется `index.html`.

## КРИТИЧНО: изоляция от «Финансы компании» (конфиденциальность)
Это приложение и `company-finance` хостятся на ОДНОМ домене
`vnyadvantage-lang.github.io` (Pages: `/family-budget/` и `/company-finance/`).
**localStorage в браузере общий на весь домен**, поэтому ключи ОБЯЗАНЫ быть
уникальными для каждого приложения — иначе данные двух проектов перепутаются.
- Бюджет использует ключи: `bali_v5` (данные), `cloud_cfg_budget_v1` (адрес облака).
- «Финансы компании»: `compfin_v1`. Никогда не переиспользовать имена ключей между
  приложениями и не добавлять общих (`cloud_cfg_v1` и т.п.).
- Облака разные: бюджет — проект `gvbrnepoekrmupgjvvri`, таблица `budget`;
  финансы — `emimuzzdglwuncjpkwoe`, таблица `finance`. Не путать.
- Данные E2E-зашифрованы своими паролями; желательно РАЗНЫЕ пароли у двух приложений.
- Для полностью раздельных «песочниц» браузера нужен раздельный домен (свой домен на
  каждое приложение или отдельный GitHub-аккаунт) — пока этого нет.

## КРИТИЧНО: сохранность данных
Данные пользователя зашифрованы (E2E) и хранятся в localStorage/облаке.
**Нельзя терять данные и сбрасывать логин/пароль.**
- Формат данных менять только обратносовместимо.
- Новые поля подмешивать через `mergeDefaults()` (а не перезаписывать).
  Курсы валют мёржатся так: `d.rates={...defData().rates,...d.rates}` —
  поэтому новые курсы появляются у существующих пользователей, не затирая их.

## Облако (Supabase) и устойчивость к его падению
- Бэкенд — бесплатный проект Supabase (REST, таблица `budget`, строка `id='main'`,
  колонка `data` jsonb с зашифрованным конвертом, RLS открыта для `anon` —
  безопасно, т.к. данные E2E-зашифрованы).
- Конфиг: `CLOUD_DEFAULT` (url + публичный ключ `sb_publishable_…`) в коде. Адрес
  можно **переопределить из UI** (Настройки → Облако) — сохраняется в localStorage
  `cloud_cfg_v1`, читается `loadCloudCfg()`; `CLOUD` — `let`, не `const`.
  Это чтобы переподключить новый проект Supabase БЕЗ правки кода и редеплоя.
- Вход устойчив к недоступному облаку: при ошибке `cloudGet()` вход НЕ блокируется —
  грузим локальный зашифрованный кэш (`bali_v5`), офлайн-режим (`_cloudDown`,
  индикатор «☁︎ офлайн · сохранено»). Если облака нет И локальной копии нет —
  НЕ создаём пустые данные (иначе пустышка затрёт облако при его возврате).
- `persist()` всегда пишет localStorage ПЕРВЫМ (данные не теряются), потом облако;
  офлайн-правки до-синхронизируются, когда облако вернётся.
- Анти-пауза: `.github/workflows/keepalive.yml` пингует Supabase раз в ~3 дня.

### Авторитетность данных (КРИТИЧНО — против потери данных)
ОБЛАКО — авторитетный источник при входе/восстановлении (`loadEnvelopes`). Локальная
копия берёт верх ТОЛЬКО при несинхронизированных офлайн-правках (флаг `bali_v5_dirty`,
ставится в persist при неудачной заливке, снимается при успешной). Иначе грузится
облако, локальный кэш освежается. Это не даёт устаревшей локальной копии затереть
свежее облако (инцидент: вход офлайн по старой локали показал устаревшие данные).
Перед заливкой dirty-локали прежняя облачная версия сохраняется в `bali_v5_cloud_backup`.
НЕ возвращать выбор «по updated/таймстампу» — таймстамп локали бампается при офлайн-
правке и делает устаревшее «новее» (это и есть затирание).

### Ежедневный бэкап
`maybeDailyBackup()` при входе раз в день: тихий зашифрованный снимок в браузере
(`bali_v5_bk_<date>`, последние 14) + опц. файл на диск (тумблер `#st-autobk` →
`bali_v5_autobk`, по умолчанию вкл). Офлайн не бэкапим (данные могут быть устаревшими).

### Runbook восстановления облака
1. Диагностика: `dig +short <ref>.supabase.co` — если NXDOMAIN при живом
   `supabase.com`, проект спит/удалён.
2. https://supabase.com/dashboard → проект. Если **Paused** → **Restore**
   (≤90 дней с паузы данные целы). Адрес/ключ те же → ничего в коде менять не надо.
3. Если проект пропал/удалён → создать новый, выполнить SQL таблицы (показан в
   Настройки → Облако), вставить новые URL+ключ в панель «Облако» (мгновенно для
   этого устройства). Для всех устройств — обновить `CLOUD_DEFAULT` в коде и
   задеплоить.
4. Логин/пароль при этом НЕ меняются: пароль — это ключ шифрования, он не привязан
   к проекту Supabase; данные при первом входе берутся из локального кэша (тем же
   паролем) и заливаются в новое/восстановленное облако.

## Валюты
Поддерживаются: **IDR** (база, рупия), **USD**, **THB** (тайский бат),
**UAH**, **USDT**, BTC, ETH.
Базовая валюта расчётов — IDR. Курсы хранятся в `D.rates`:
- `usdIdr` — рупий за 1 USD
- `thbIdr` — рупий за 1 THB
- `uahIdr` — рупий за 1 UAH
- `usdtUsd` — USD за 1 USDT

### Зафиксированные курсы по умолчанию (defData)
При курсе **1 USD = 17000 IDR**:
- `usdIdr: 17000`
- `thbIdr: 580` (бат зафиксирован относительно этого курса доллара)
- `uahIdr: 400`
- `usdtUsd: 1`

Эти же значения продублированы как запасные (fallback) в обработчике
сохранения курсов (`btn-save-rates`).

### Где трогать код при добавлении/правке валюты
- `defData().rates` — значения по умолчанию
- `toIdr(amt,ccy)` и `rateFor(ccy)` — конвертация в рупии
- `CSYM` — символ валюты, `CCOLS` — цвет в разбивке по валютам
- `calcAccTotals()` / `rAccTotals()` — сводка по счетам
- селект `#am-ccy` (создание счёта), селекты `#sn-ccy` / `#vo-ccy` (доход)
- модалка курсов `#m-rates` (поля `r-usd`/`r-thb`/`r-uah`/`r-usdt`) и её
  обработчики открытия/сохранения; онлайн-подтяжка в `fetchRatesOnline()`
- зачисление дохода на счёт: ветки расчёта `credited` в
  `applyEntryToBalances()` и `addInc()`
